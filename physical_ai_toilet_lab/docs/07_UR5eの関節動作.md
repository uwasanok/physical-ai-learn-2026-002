# 既製UR5eを使って曲面清掃を動かす

## 今回の成果

公式のUR5eモデルから、各リンクの寸法・回転軸・関節制限・衝突用3D形状を読み込んだ。
先に作ったカメラ由来の清掃軌道（seed42、32動作、3,360点）を6関節の角度に変換し、
アーム付きの3D再生画面にした。

**これは関節運動の幾何的な試作。動力学シミュレーションや実機を動かすプログラムではない。**

## 何を使い、どう動かすか

1. Universal Robotsの公式XacroをROS 2 Jazzyの `xacro` で展開し、URDFを作る。
2. URDFの関節位置・回転軸・上下限をPythonで読み込む。
3. ブラシの希望するxyzと向きに対し、SciPyの数値計算で6関節の角度を求める（逆運動学／IK）。
4. 求めた角度から先端位置を再計算する（順運動学／FK）。希望位置との誤差を確認する。
5. FKで得た実際の先端位置・向きを簡易清掃モデルに渡す。表示の汚れも、この再計算に基づいて更新する。

ブラシのz軸は便器面へ向かい、柄はその反対方向へ伸びる。円形ブラシなので軸回りの向きは固定規則で決める。
工具の長さはtool0から180mmを仮定。アームの形状は公式の衝突用STLで、外観用の精細モデルとは細部が異なる。

## 仮置きした設置条件

|項目|今回の値|
|---|---|
|アーム根元の位置|世界座標 (0, -0.52, 0.55)m|
|台の外形|幅440×奥行450×高さ550mmの箱として表示|
|台の範囲|x=±0.22、y=-0.75〜-0.30m|
|ブラシ先端|tool0の+z方向へ180mm|
|便器|前段階と同じ仮の曲面|
|カメラ|(0, -0.65, 1.0)m。支柱の詳細は未設計|

台は実在する市販型番ではなく、UR5eを載せる専用架台の寸法案。
強度・重心・取付ボルト・制御箱の収まりはまだ設計していない。

## 確認した結果

- 全3,360点で指定した先端位置・姿勢を満たすIK解を取得。
- 公式URDFの関節制限内。肘の±180度のモデル上の制限も適用。
- 清掃区間内の隣り合う点の関節角度差は最大約0.317度。
- FKの先端位置で清掃を再計算し、最後の残留区画数は0。
- 公式STLの頂点による簡易検査では、便器の仮の固体領域や台への入り込みを検出しなかった。
- 既存分を含む18テスト成功。ゼロ姿勢での公式リンク寸法との整合、IK→FKの一致、到達不能点の不成立も確認。
- HTML描画はJavaScriptの構文と、先頭・中間・末尾の模擬Canvas実行を確認。別途Pythonの静止画も確認。

IKの数値誤差が極小なのは、同一の理想モデルで逆計算と順計算を行っているため。実機の位置精度を示す結果ではない。
今回はseed42のみをアームに接続。別配置や便器形状でのアーム評価はこれから。

## 未完了の点

**清掃場所を切り替える移動経路は未計画。** 区間境界では最大約69度の関節角度差がある。
表示は次の清掃開始姿勢へ切り替わる。間をそのまま補間して実行できるとは判断しない。

自己衝突と厳密な三角形同士の衝突検査は未実装。頂点検査は面の交差や工具の干渉を見落とし得る。
関節速度・加速度・トルク・特異点余裕も未評価。
カメラ画像生成にはまだアームの遮蔽を入れていない。3D画面のアームは検証表示であり、認識画像に映り込む処理は次段階。

次は退避点を挟んだ区間間の経路計画と、自己衝突・便器・台・工具の干渉検査を追加する。
細かい接触力の再現は引き続き後回しにする。

## 開くファイル

- `output/ur5e/ur5e_cleaning_3d.html`：アーム付き3D再生。ドラッグ回転、拡大、時間送り、関節角度表示。
- `output/ur5e/ur5e_preview.png`：異なる清掃姿勢を2方向から見た静止画。
- `output/ur5e/joint_trajectory_rad.csv`：6関節の角度。単位rad。実機投入用ではない。
- `output/ur5e/verification.json`：検証結果と制限。
- `output/ur5e/ur5e.urdf`：公式Xacroから展開したモデル。

## 再実行

プロジェクトのルートで、同じ一時コンテナを使う。Step1の稼働コンテナは変更しない。

```powershell
docker run --rm --network none --mount "type=bind,source=$PWD,target=/work" -w /work physical-ai-step1:jazzy bash scripts/export_urdf.sh
docker run --rm --network none --mount "type=bind,source=$PWD,target=/work" -w /work/scripts physical-ai-step1:jazzy python3 build_ur5e_motion.py
docker run --rm --network none --mount "type=bind,source=$PWD,target=/work" -w /work/scripts physical-ai-step1:jazzy python3 render_ur5e_preview.py
docker run --rm --network none --mount "type=bind,source=$PWD,target=/work" -w /work/scripts physical-ai-step1:jazzy python3 -m unittest -v
node scripts/test_viewer_runtime.cjs
```

公式ソースは `vendor/ur_description` に取得。jazzyブランチのコミット
`7ce98d8c3512b9d0239da93b75de68ea64f61bd6` を今回の基準とする。
生成物はこの版で検証済み。将来のブランチ更新を自動的に混ぜない。
