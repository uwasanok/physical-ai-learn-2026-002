# 清掃場所の切り替えと衝突検査

## 今回できたこと

以前は清掃区間だけを動かし、次の場所に姿勢が飛んでいた。
今回は「清掃→面から離れる→次の場所へ移動→面へ接近→清掃」をつなげた。
対象は前段階と同じseed42の汚れ配置。新しい試験環境で23件のテストが通った。

開くファイル：`output/continuous/continuous_cleaning_3d.html`

表示では「接近・清掃・退避・場所の切り替え」を区別し、予定時刻も表示する。
予定時間の約3倍速で再生。初期状態は検査済みの退避姿勢であり、電源投入姿勢からの起動動作は含まない。

## 何を使って、どう実装したか

- 公式UR5eの関節構造・衝突用STLはそのまま使用。
- python-fcl 0.7.0.8を追加した専用Dockerイメージ `physical-ai-toilet:collision` を作成。
- FCLでアームの三角形メッシュ同士、便器メッシュ、筐体・床・カメラ・支柱・ブラシ・柄を検査。
- 便器は仮の楕円放物面に外壁と底面を付けた閉じたメッシュ。実便器の縁や外装の細部はまだない。
- 清掃終了点から面の法線方向へ80mm退避し、次の開始点の80mm手前へ移動してから接近。
- 退避と接近は先端座標を1mm以下の間隔で計算。各区間をさらに関節角度差0.25度以下に分割して検査。
- 80mmの案で失敗する場合は120mm、160mmを試す。今回の31区間はすべて80mmで成立した。

移動区間は関節空間での線形補間。万能な障害物回避探索ではない。
候補が全部不成立なら成功した連続経路として生成せず停止する設計。
FCL参照元：https://github.com/BerkeleyAutomation/python-fcl

## 検査で許可する接触

関節の継ぎ目を構成する隣接リンク、柄と手首、ブラシと柄は自己衝突の検査対象から除外する。
アーム根元と台の固定部も除外。除外ペアはverification.jsonに記録する。

ブラシと便器は常に除外するのではない。
接近・清掃・退避中で、先端が対象曲面から4mm以内、対象領域内、軸の向きが面法線から25度以内の場合だけ許可する。
移動中は同じブラシ位置でも便器との接触を検出する。柄・手首・その他のリンクにはこの例外を適用しない。

|---|---:|

|動作間の切り替え|31区間|

|設定した関節速度上限|15度/秒|

予定時間は各検査点の時間刻みを最低20msとし、関節速度上限も満たすよう付けた値。
実機の清掃時間ではなく、撮影・推論待ち時間や加速度制限も含まない。

清掃の判定はFKで計算した先端位置から行う。移動中の経路を清掃回数として加算しない。
今回は保存済みのカメラ由来の清掃目標列を経路化している。アームによる画像遮蔽や移動中の再認識は未接続。

## テストで確認したこと

既存18件に次の5件を追加した。

1. 頂点の一致がなくても、三角形が交差する状況を検出する。
2. ブラシ位置に追加した障害物を検出する。
3. 自己衝突する関節姿勢を検出する。
4. 全13,793点を再検査し、関節の飛び・速度上限・衝突を確認する。
5. 意図した清掃接触だけ許可し、移動フェーズでは同じ接触を検出する。

HTMLは模擬Canvasで先頭・中間・末尾の実行を確認。静止画も生成して確認した。
ブラウザ操作ツールのローカルHTMLアクセス制限があるため、実ブラウザ上での操作検証は未実施。

## 残る限界

これは細かいサンプル点での衝突検査であり、連続時間で絶対に衝突しないという数学的保証ではない。
三角形メッシュの離散化や、完全に内部に包含される場合など、メッシュ検査特有の限界も残る。
実物の便器・筐体・ケーブルなどの形状、リンクのたわみ、加速度・トルク・特異点余裕は未評価。
接触の力学は希望どおり簡略化したまま。実機へ送る軌道として扱わない。
アーム・経路の評価はseed42のみで、他の汚れ配置と便器形状への展開は次段階。

## 再実行と成果物

```powershell
cd ./physical_ai_toilet_lab
docker build -t physical-ai-toilet:collision .
docker run --rm --network none --mount "type=bind,source=$PWD,target=/work" physical-ai-toilet:collision python3 plan_continuous_motion.py
docker run --rm --network none --mount "type=bind,source=$PWD,target=/work" physical-ai-toilet:collision python3 -m unittest -v
docker run --rm --network none --mount "type=bind,source=$PWD,target=/work" physical-ai-toilet:collision python3 render_continuous_preview.py
node scripts/test_viewer_runtime.cjs output/continuous/continuous_cleaning_3d.html
```

Step1のDockerイメージは基礎環境として参照しただけで、Step1のコンテナ・コード・提出物は変更していない。
全テストにはFCLが必要なので、今後はこのラボ用イメージを使う。

- `output/continuous/verification.json`：検証結果・例外・制限。
- `output/continuous/planning_attempts.json`：移動経路の候補と採否。
- `output/continuous/joint_trajectory.csv`：予定時刻と6関節角度（rad）。
- `output/continuous/motion.npz`：関節角度、動作フェーズ、清掃番号、時刻。
- `output/continuous/continuous_preview.png`：退避軌道と関節角度の確認図。
