# 便器の形状と、学習前に固める試験条件

## 今回の位置づけ

学習の前に、形状・可視範囲・アームの到達性を検討する段階。
便器の縁を追加したところ、旧設定では手首が干渉することが判明した。
同じ汚れ・同じ清掃範囲のままブラシの柄を延長して比較し、次の学習実験の基準案を作った。
今回も学習済みAIは未使用。認識は茶色の条件判定。

## 形状をどう変えたか

従来の単純な楕円放物面に対し、底を緩やかに、上部の壁を急に立ち上がる曲面に変更した。
さらに、内側へ張り出す縁を別の立体形状として追加した。

|部位|仮の寸法・形状|
|---|---|
|内面|幅360mm、奥行480mmの楕円領域|
|底|高さ220mm。中心付近は緩やかな曲率|
|内壁上端|高さ400mm|
|縁|上面425mm、下面395mm。内面の半径倍率0.94〜1.14の楕円環|
|最大外幅・外奥行|約410mm・547mm|

内面は s=(u/0.18)²+(v/0.24)²、z=0.22+0.04s+0.14s² で表す。
縁の張り出しはこの高さ関数だけでは表せないため、別の閉じた3Dメッシュにしている。
カメラの視線計算でも縁の上下面・内外側面・便器外壁による遮蔽を扱う。
衝突検査では縁を清掃接触の例外から外し、手首もブラシも縁に当たれば不成立とする。

**寸法は設計用の仮定であり、メーカーCADや実測した便器の再現ではない。**
排水口、便座、洗浄水、実際の陶器の細部は含まない。

## 清掃範囲を先に固定する

カメラは前方の筐体上 (0,-0.65,1.0)m、640×480画素で固定。
清掃範囲は従来どおり u=-0.11〜0.11m、v=0.025〜0.155m の奥側領域。
失敗する場所を試験後に除く操作はしていない。

- 清掃範囲の検査点：1,904点。便器・縁に対して全点が見える。
- 内面全体の検査点：8,323点中5,558点が見える。手前側には死角がある。
- これは格子点の数であり、表面積の可視率ではない。
- アームによるカメラ遮蔽はまだ含まない。実用的な撮影条件の確定には、観測時のアーム退避姿勢の検証が必要。

今回のゴールはこの限定領域。見えない面まで清掃完了と判断しない。

## 同じ条件で柄の長さを比較

試験配置は42、123、999、2026、53772の5seed。各配置にn=1、3、5回で落ちる汚れを混ぜる。
乱数で汚れ位置・大きさ・nとの対応を変えた。いずれも開発用で、学習後の最終評価用ではない。

|seed|180mmの柄|260mmの柄：清掃回数|260mmの柄：残留区画|
|---|---|---:|---:|
|42|接近中に手首と縁が干渉|35|0|
|123|途中の接近経路が不成立|26|0|
|999|接近中に手首と縁が干渉|37|0|
|2026|途中の接近経路が不成立|32|0|
|53772|途中の接近経路が不成立|29|0|

260mm案では手首を高く保てるようになり、5配置すべてで清掃・退避・移動・接近の経路が得られた。
必要に応じ退避距離80/120/160mmの候補を検査し、不成立の候補もログに残した。
清掃判定には関節角度から再計算した先端位置を使っている。

180mmで絶対に清掃できないという証明ではない。今回の設置位置・IKの選択・経路生成方法での失敗であり、
別の姿勢や設置方法なら成立する可能性がある。260mmも最適長ではなく、成立を確認した比較案。
長くした工具のたわみ・トルク・強度は未評価。

最終確認では5配置の全67,072姿勢を独立に読み直して、FCL検査・関節刻み・清掃残留を再確認した。
形状法線の数値検査、カメラと曲面の往復変換、死角、180mm工具での接近中の縁との干渉も含め、計28テストが成功。
3D表示は模擬Canvasで先頭・中間・末尾を実行確認し、別途静止図を目視確認した。
ブラウザ操作ツールのローカルファイル制限により、実ブラウザ上の操作確認は未実施。

## 再現用の記録

- `config/study_v1.json`：形状・カメラ・清掃範囲・seedなどの実験条件の記録。
- `output/geometry_trials/tool_180mm/`：短い柄の不成立記録。
- `output/geometry_trials/tool_260mm/`：長い柄の経路、結果、画像。
- `output/geometry_trials/tool_260mm/toilet_with_rim_3d.html`：新形状と260mm工具の3D再生（seed42）。
- `output/geometry_trials/geometry_and_trials.png`：形状・死角・比較結果の図。
- `scripts/toilet_geometry.py`：形状とカメラの計算。
- `scripts/geometry_trials.py`：複数配置の一括試験。

configは条件の記録。実装値の定義元はPythonコードであり、JSONだけを書き換えて形状が自動変更される機能はまだない。
最初の試行のファイルが `output/geometry_trials/` 直下にもあるが、比較の確定結果には上記のtool別ディレクトリを使う。

```powershell
cd ./physical_ai_toilet_lab
docker run --rm --network none -e TOILET_TOOL_LENGTH=0.18 --mount "type=bind,source=$PWD,target=/work" physical-ai-toilet:collision python3 geometry_trials.py
docker run --rm --network none -e TOILET_TOOL_LENGTH=0.26 --mount "type=bind,source=$PWD,target=/work" physical-ai-toilet:collision python3 geometry_trials.py
docker run --rm --network none --mount "type=bind,source=$PWD,target=/work" physical-ai-toilet:collision python3 -m unittest -v
docker run --rm --network none --mount "type=bind,source=$PWD,target=/work" physical-ai-toilet:collision python3 render_geometry_study.py
```
